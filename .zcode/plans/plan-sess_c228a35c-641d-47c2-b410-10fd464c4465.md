# Saarthi Booking Flow — Audit & Redesign Plan

## 1. Audit findings (pre-implementation report)

**Files responsible for the booking flow** (all under `src/components/booking/` unless noted):
- `src/app/(public)/book/page.tsx` + `BookClient.tsx` — thin page wrappers
- `BookingSystem.tsx` (517 lines) — step state (`useState(1..7)`), slot lock lifecycle, Razorpay load → `createBooking` → `verifyPayment`, success screen
- `BookingLayout.tsx` — two-column shell: `lg:grid-cols-[minmax(0,1fr)_20rem]`, sticky right rail (`hidden lg:sticky lg:top-8`), single column below lg
- `BookingStepper.tsx` — icon stepper (sm+) + compact progress bar (mobile)
- `BookingSummary.tsx` — `variant="sidebar"` (desktop rail) and `variant="mobile"` (collapsible bar above content, steps ≥ 2)
- `steps/`: TherapistStep, SessionTypeStep, DateStep, SlotStep, DetailsStep (react-hook-form + zod), ReviewStep (also exports `BookingFlowState`)
- `bookingUi.ts` + `bookingUi.test.ts` — pure display helpers; `SESSION_PRICE_DISPLAY = "₹1,500"`, `CONFIRM_CTA_LABEL`, `STEP_LABELS`

**Typography system**: Tailwind v4 CSS-config in `globals.css`. Fonts via `next/font/google`: Inter (`--font-sans`, body default) + Playfair Display (`--font-serif`, applied to ALL h1–h6 globally). Booking components then layer a "luxury" micro-label pattern everywhere: `text-[10px] font-black uppercase tracking-widest` labels + `font-serif font-bold` values — this is the poor-typography problem. No new font dependencies needed.

**Animation system**: framer-motion 12.42.2 (installed, used in every step). Step transitions = `AnimatePresence mode="wait"` + keyed fade/rise (BookingSystem.tsx:485–495). `useReducedMotion` already respected. Note: `animate-in fade-in zoom-in-95` classes on the verifying-payment modal (BookingSystem.tsx:501) are dead — no tw-animate plugin installed.

**How Details → Review works today**: DetailsStep submit → `handleDetailsSubmit` merges form data → `setStep(6)`. The sidebar `BookingSummary` renders for ALL steps including 6, and ReviewStep re-renders nearly the same data in its own card → the duplication the user sees.

**Verified**: Details pill uses `SESSION_DURATION_MINUTES` (= 45, `src/shared/constants/index.ts:13`) — no "60 minutes" wording anywhere. Price display traces to the single `bookingUi.ts` constant; actual charge is server-computed (`domains/booking/utils/pricing.ts`).

## 2. What changes (and what doesn't)

**Untouched**: all handlers in BookingSystem (`handleConfirm`, Razorpay, lock/verify flow), `useBooking`, services, schema, pricing, `BookingFlowState` lifecycle, slot/availability logic, analytics. Only JSX structure, classNames, and animation wrappers change.

## 3. Details → Review shared-element transition (core work)

**Mechanism**: framer-motion `layoutId` (already a dependency — no new libs).

1. **BookingLayout.tsx** — make columns `motion.div layout` so the grid animates between `lg:grid-cols-[minmax(0,1fr)_20rem]` (steps 1–5) and a single centered column (step 6). Respect `useReducedMotion` (skip layout animation).
2. **BookingSystem.tsx** — restructure the wizard body:
   - Sidebar `<motion.div layoutId="booking-summary-card" style={{borderRadius:'2rem'}}>` wraps `BookingSummary variant="sidebar"`, rendered only while `step < 6`.
   - Steps 1–5 keep the existing `AnimatePresence mode="wait"` fade/rise.
   - **ReviewStep renders OUTSIDE that AnimatePresence** (in its own AnimatePresence with opacity-only exit for graceful back-nav). This is the key structural change: when "Review Request" is clicked, one React commit simultaneously (a) unmounts the sidebar card, (b) mounts the review card with the same `layoutId`, (c) pops Details' exit fade. framer-motion FLIP-animates the card from its right-rail bounds to the centered position while it grows — same card, continuous identity, no disappear/reappear.
   - Review card internals: the sections shared with the sidebar (therapist header, Session/Date/Time rows, Total box) render identically for visual stability; review-only sections (client details, contact, note, consent echo) are present at full height but fade in with a short delay so the card morphs at final size, then details settle in.
   - Reduced motion: `layoutId` omitted entirely → simple fade/state swap (existing behavior).
   - Mobile: the collapsible summary renders for steps 2–5 only; on step 6 the centered review card replaces it with a fade/rise (no desktop morph forced onto mobile). Review card is full-width readable, no horizontal overflow.
   - Back (Review → Details) reverses: review fades out, sidebar remounts and the card morphs back.
3. **ReviewStep.tsx** — rebuild: "Final Review" title + "Take a moment to check your session details before payment." subtitle → slot-hold banner (unchanged) → the shared centered card (renders `BookingSummary variant="review"` inside the `layoutId` wrapper) → error banner + "Pick Another Slot" (unchanged logic) → Back / Confirm & Pay buttons, stacked on mobile. All its own duplicate details grid removed. `getButtonContent`, `isBusy`, `isLockExpiredError` logic byte-identical. Price/duration from `bookingUi.ts` / `SESSION_DURATION_MINUTES` only.
4. **BookingSummary.tsx** — add `variant="review"` accepting optional client props (name, email, phone, note, consent) sourced from existing `bookingData`; unify sidebar/review card surface (same border/radius/shadow/background) so identity holds during the morph.

## 4. Typography redesign (booking-scoped only; globals.css untouched)

Consistent hierarchy applied across all 8 booking files — Playfair kept **only** for the six step titles and "Final Review" (reduced to `text-2xl sm:text-3xl font-semibold tracking-tight`); everything else Inter:

| Role | Before | After |
|---|---|---|
| Micro labels (summary rows, form labels, stepper) | `text-[10px] font-black uppercase tracking-widest` | `text-xs font-medium text-muted-foreground` (sentence case, no tracking) |
| Values (summary rows, review grid) | `font-serif font-bold` | `font-sans font-semibold text-primary` |
| Price | serif bold | `font-semibold tabular-nums text-primary` (size for prominence) |
| Section/card titles | serif bold | `font-sans font-semibold text-primary` |
| Buttons | `font-bold` overrides | default `font-medium`, keep existing hover/active |
| Supporting text | mixed | `text-sm text-muted-foreground` |
| Stepper labels | `text-[11px] font-bold uppercase tracking-wider` | `text-xs font-medium` |

No uppercase eyebrows, no wide tracking, no serif on data — kills the fashion-site feel while keeping brand serif for headings.
